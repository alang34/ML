# Changelog

These entries group the current local changes by feature since `v1.0.a` (commit `416bcff`). The version labels describe the changes in this working tree.

## v1.d — Vorticity supervision

- **Added signed wake vorticity to the training objective.** The model computes streamwise vorticity from the velocity reconstructed by the vector potential, using `dw/dy - dv/dz`. It compares that result with OpenFOAM's `vorticity_0` export. This gives training a direct signal about the direction and strength of wake rotation, beyond the velocity error at individual points. The SST field named `omega` is a separate quantity.
- **Kept the added training cost bounded.** Each step samples up to 64 wake points per case, preferring the persistent wake subset. Vorticity is expressed in units of `u_ref / l_ref`, and the Smooth L1 error uses a fixed training RMS scale for each case. The default loss weight is `0.05`. The model still learns four channels and requires only position and reference speed at inference.
- **Added wake validation and a total-loss breakdown.** The dashboard shows relative L2 on a fixed set of held-out wake points and plots the weighted vorticity term. It also reports how much of the total objective comes from CFD velocity and pressure, boundary conditions, vorticity, momentum, and mass continuity. Weighted parameter-gradient norms are sampled on the first step and every 250 epochs by default. These norms show the size of each term's gradient before Adam, while gradients from different terms can reinforce or cancel. Mass continuity has zero loss weight and still has its own residual diagnostic.
- **Verified sign, scaling, and integration.** An analytic flow confirmed the vorticity value and its gradient. Smoke tests on both CFD exports exercised supervised and PDE training, found 324 held-out wake points, and verified that older vector-potential checkpoint histories load with the new diagnostic columns. The effect on long-run wake accuracy remains open.

## v1.0.c — Vector potential prediction

- **Reconstructed velocity from a scaled curl.** The network learns `[ax, ay, az, p]` internally and returns normalized `[u, v, w, p]`. The curl uses the separate streamwise and cross-stream reference lengths, so the reconstructed velocity satisfies incompressible continuity up to floating-point precision. The PDE loss now averages Smooth L1 over the three momentum residuals. Momentum balance remains a training objective.
- **Reworked startup and curl evaluation.** Zero output weights start velocity at freestream, and the pressure bias uses the reference training mean. High-frequency Fourier weights start smaller to limit the initial velocity slopes that caused large crossflow L2 spikes. The forward pass evaluates the three potential derivatives together with the chain rule, which also supports inference without an autograd graph.
- **Added mesh-based boundary initialization and supervision.** A new reader loads ASCII OpenFOAM boundary geometry and velocity conditions from plain or gzip-compressed files. Training samples faces by area within each case and condition group. Slip constrains the normal component, stationary body walls constrain all three velocity components, and fixed-value patches use the prescribed velocity. Fresh runs take 200 boundary-only warm-up steps. A separate boundary loss stays active during supervised and PDE training.
- **Changed training and resume behavior.** Adam starts at `5e-5` and halves its rate every 5,000 epochs down to `1e-5`, independently of validation error. Validation runs every 20 epochs. Resume retains Adam's state and validation history and computes the scheduled rate for the next epoch. The full training monitor remains in place, includes the boundary loss, and supports validation sets smaller than 5,000 points.
- **Separated checkpoints by output representation.** The default directory is `checkpoints/vector_potential_boundaries`. Checkpoints validate the velocity representation, reference lengths, and Fourier frequencies before applying weights. Direct-velocity checkpoints from `v1.0.a` require a fresh run because their output weights have a different meaning.

## v1.0.b — Persistent point updates

- **Reserved part of each supervised batch for near-body and wake points.** With the default 50,000-point batch, the 5% reservation keeps 2,500 points fixed across refreshes. Each of the two reference speeds contributes 625 near-body points and 625 wake points. The remaining points still rotate every 250 epochs during supervised pretraining using the existing weighted sampler.
- **Defined the regions from the CFD exports.** Near-body points have a positive `wallDist` of at most 0.10 m. Wake points are farther from the body, downstream of the configured start at 3.83 m for these cases, and have a streamwise velocity deficit greater than 5%. When block names are available, selection uses interior mesh rows. Any unused quota goes back to the rotating portion.
- **Preserved the validation split and normalization.** Validation is chosen before the persistent points, and every training refresh excludes those validation rows. Model bounds and target scales still come from the original weighted training draw. With the same seed and data, resume rebuilds the persistent set and reconstructs the most recent scheduled training refresh.
